# Haaflah 2026

Haaflah is a Hacktoberfest 2026 programme built around one idea:

> Build for real businesses. Train real developers. Create open source.

The programme is designed to move contributors from first application to
production deployment through community, learning, cross-functional squads,
mentor reviews, and real SME feedback.

## What We Are Building

### Open Commerce

Open Commerce is the flagship Haaflah product: a modular, headless,
self-hostable e-commerce suite for small and medium businesses that are priced
out of traditional SaaS platforms.

The first release is planned to include:

- **Customer storefront**: Responsive catalogue, search, cart state, one-page checkout, and WhatsApp receipts
- **Merchant dashboard**: Product inventory, order fulfilment, customer logs, and revenue analytics
- **Backend platform**: JWT/OAuth authentication, REST or GraphQL APIs, local payment webhooks, and OpenAPI documentation

The core technology direction is Next.js, Tailwind CSS, Node.js or Go,
PostgreSQL, and Redis. The project is intended to use a permissive open-source
licence such as MIT or Apache 2.0.

## Programme Model

Contributors move through a ten-stage funnel:

`Application -> Screening -> Onboarding -> Squad pairing -> Training sprints -> First PR -> Feature sprints -> Demo and review -> Deployment -> SME empowerment`

Delivery squads are cross-functional groups of 8-10 people, typically made up
of a squad lead, UI/UX designer, developers, QA, and technical writing support.
Mentors, DevOps architects, speakers, and SME stakeholders support squads as
needed.

### Five-Week Sprint

| Week | Focus | Output |
| --- | --- | --- |
| 1 | Foundations | Git workflows, Docker, repository setup, and contribution guidelines |
| 2 | Specifications and architecture | PRDs, Figma review, schemas, and API decisions |
| 3 | Core feature build | Frontend/backend integration and mentor code reviews |
| 4 | QA and polish | Regression fixes, responsive improvements, and documentation |
| 5 | Deployment and Demo Day | Release tagging, cloud rollout, SME onboarding, and impact showcase |

The weekly rhythm is Monday alignment, Friday integration testing, and Sunday
PR merge deadlines.

## SME Solution Lifecycle

Partner businesses provide regular prototype feedback and testing in exchange
for free custom software delivery and production onboarding.

1. Business application and bottleneck identification
2. 45-minute diagnostic discovery call
3. Four-week MVP scoping and PRD finalisation
4. Dedicated squad development sprint
5. Staging UAT with real inventory
6. Production handover and admin credentials

## Programme Targets

- **500+** registered participants
- **100+** merged high-quality pull requests
- **50+** first-time contributors
- **5+** production-deployed SME solutions

The primary focus metric is the number of participants who become confident,
real-world software builders.

## Getting Started

### Requirements

- Node.js 20 or newer
- npm

### Install and run

```bash
npm install
npm run dev
```

The development server uses port `3000` by default. If that port is occupied,
Vite selects the next available port.

### Available scripts

```bash
npm run dev              # Start the Vite development server
npm run generate-routes  # Regenerate TanStack Router route types
npm run build            # Create a production build
npm run preview          # Preview the production build locally
```

## Project Structure

```text
src/
  components/       Shared header, footer, and UI components
  routes/           File-based TanStack Router routes
  styles.css        Global theme, layout, responsive styles, and animations
public/              Static assets including the Haaflah logo and favicon
content/             Markdown content collections retained for future programme content
```

`src/routeTree.gen.ts` is generated by TanStack Router. Add or rename route
files inside `src/routes/`, then run `npm run generate-routes` instead of
editing the generated file manually.

## Deployment

The project is configured for a Vercel-compatible TanStack Start deployment.
Build the application with:

```bash
npm run build
```

The production output is generated by Nitro. Environment variables should be
configured in the deployment provider rather than committed to the repository.

## Roadmap

After the first Open Commerce release, the planned expansion includes dispatch
and courier tracking, service booking, recurring subscriptions, multi-vendor
support, and automated accounting.
